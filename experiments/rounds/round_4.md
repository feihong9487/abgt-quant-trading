# ABGT 優化迴圈 — 第 4 輪回合報告

日期：2026-09-23　｜　基準：`ema50_plain`（六格平均 Sharpe 1.09、十格全過、holdout SOL 5/5 / BNB 3/5）　｜　本輪變體：4 個（graded_exposure 2 個策略類 + running_gate 2 個運行閘門類）　｜　實作失敗：0　｜　驗證：3 個各做 lookahead / overfit / executable / holdout 四道（A3 在實作者自檢階段即依事前判準 fail，未送驗）

## 0. 結論一句話

**無新冠軍，基準維持 `ema50_plain`；graded_exposure 方向（第 3 輪唯一留下的策略線索）與 hold 型運行閘門方向都依事前判準關閉。現貨紙上前向以 `ema50_plain` 單獨開始，不掛任何倉位覆蓋層、不掛自動動作的運行閘門，運行閘門只做記錄。**

本輪是第 3 輪安慰劑結論的直接後果：把取代門檻改成「四 OOS 格 Δ 平均 ≥ +0.05 且至少一格 |t| ≥ 1.5」或「四 OOS 回撤全淺 ≥ 3 pp」之後，第 3 輪數值全達標的消融 A3 正式化（`graded_exposure_ema_exit_ratchet_a3`）**逐位重現了第 3 輪的數字（六格 1.148、四 OOS Δ −0.040/−0.043/+0.029/+0.103），但 150 次回合路徑置換的安慰劑把它放在第 83 / 69 百分位，10.7% 的隨機路徑同樣滿足全部數值門檻**——距離 (close−EMA50)/ATR 對「哪個回合會失敗」沒有超出隨機分配的資訊。2×2 缺格 clip 版（`graded_exposure_ema_exit_clip_d05`）給出四輪以來 BTC 上最強的 OOS 證據（BTC OOS +0.135 t 1.73、OOS2 +0.176 t 1.85、去前 3 段後 t 1.92/2.18、安慰劑第 94–99 百分位、回撤比 96–100% 安慰劑淺），但同一規則在 ETH 五格全負（IS2 掛）、BNB 五格全負（OOS2 翻掛），機制檢查證明原因：**「上膛後回到 EMA50 0.5 ATR 內」在 BTC 是出場前兆（半倉根次日 −0.65%/日、Welch t −2.6），在 ETH/BNB 是續漲前的回檔（+0.26%～+0.92%/日）**——減半的正負號依標的翻轉，且 BTC 的證據來自假設形成所用的同一段 2024–26 資料（OOS 只取 2023：Δ +0.022、t 0.04）。

運行閘門兩個變體（累計 20% → hold 60 根；滾動 180 根 20% → hold 60 根）給出比「不採用」更強的結論：**以策略自身權益對持有的比值作為觸發量，觸發時點是成本模型與起算日的函數**（五個壓力情境五套觸發集合；成交價加 σ=0.05% 雜訊 20 個種子 ETH 出現 13 種週期集合；起算日逐月掃描 BTC 70 個起點 42 個觸發、Δ 平均 −0.066），且「累計落後 20%」在牛市裡是趨勢跟隨的正常運行區間而非尾部事件（以 2023-01-01 為基期 plain 在 BTC 2024-05-15、ETH 2023-07-07 就穿 −20%；14 個季度上線日 BTC 9 / ETH 11 會觸發）。hold 動作等於在頂部觸發後關掉唯一的風控（趨勢出場），安慰劑（同長度隨機放置的 hold）在兩標的都優於實際時點。CLAUDE.md §1「落後超過 X% 自動轉持有」這條字面設計在本輪被完整否定，實盤只保留記錄。

**給紙上前向的 guard 規格（記錄型，不動作）**：引擎 `RiskParams.lag_stop = 0`（閘門關閉）；紙上前向每日另算並記錄（不進引擎）：(a) 單位化 NAV（份額法排除出入金）與同起點（上線日）買入持有 NAV 的比值；(b) 比值自其高水位的回撤（rel_dd 口徑）；(c) 90/180/365 根滾動比值（前 180 根標示為盲區）；(d) 策略自身絕對回撤與連續鋸齒次數。累積 ≥ 6 個月後用「各上線日 cohort 的累計落後分布」決定是否還值得設計 X（取 cohort 最深落後 p95 以外），且動作只能是「通知 / 人工覆核」，不可自動轉持有。CLAUDE.md §1「運行閘門」列的狀態改為「hold 型已測、否定（第 4 輪）；改記錄型」。

## 14. 引擎 / 風控模型改進提案（需改 `abgt/strategies/regime.py` 或新增模組）

本輪前已實作第 3 輪 P1（lag_stop 系列）、P2（scale_mode / scale_floor）、P3（fills_by_reason / notional_turnover / rel_dd_vs_hold / lag_events），不再提。以下是本輪暴露且與「轉向執行面」一致的缺口。

### P1. 雙標的組合引擎 `simulate_portfolio`（第 3 輪 P4，仍未實作，現在是紙上前向的前提）

- 介面：`simulate_portfolio(dfs: dict[str, DataFrame], regimes: dict[str, in_regime], rp: RiskParams, weights: dict[str, float], start_idx)`：一本共用權益的 `Book`（`broker.py` 支援多標的 entries）、每標的目標曝險 = `weights[s] × max_exposure × scale`、`rebalance_threshold` 逐標的判定、資金費率逐標的；基準 = 同權重買入持有（不再平衡與月再平衡各一）；索引取交集、缺根視為該標的 regime False；`extra` 逐標的 fills 與組合層 rel_dd_vs_hold。
- 動機：實際上線交易的是 BTC+ETH 現貨，紙上前向的 NAV、基準與任何運行紀錄都在組合層定義；單標的 Sharpe 看不到鋸齒的跨標的分散，ETH 對持有 0.045 的薄邊距在組合裡可能被 BTC 吸收也可能拖垮。這是「部位表示」最後一個沒測的維度，且不需要新的 regime 規則。

### P2. 運行閘門改記錄型與高水位基期：`lag_action="record"`、`lag_base_mode`、`lag_retrigger_cooldown`

- 欄位：`lag_action` 加 `"record"`（只寫 `lag_events`，不改目標曝險）；`lag_base_mode: str = "reset"`（現行：起算根 / 上次恢復根）| `"hwm"`（對比值高水位量測，= rel_dd 口徑，恢復不重設基期）| `"start_only"`（永遠對 start_idx，不重設）；`lag_retrigger_cooldown: int = 0`（恢復後 N 根內不得再觸發，消除鏈接點來回）；`extra.lag_min_margin`（每格內 lag 距 −lag_stop 的最小距離）。
- 動機：本輪三位驗證者各自證明現行 `lag_base` 重設語意讓「鎖定」變向下棘輪、鏈式再觸發付 3–9 pp、OOS 無觸發被讀成無害。記錄型是紙上前向唯一允許的用法；`hwm` 是 CLAUDE.md §1 原意的正確量測；`lag_min_margin` 讓「ETH OOS 最小 lag 離門檻 3 pp」這種刀鋒一眼可見。**不是**為了再開 hold 型變體，是為了讓記錄與未來的 cohort 校準用同一套引擎語意。

### P3. 評估器對路徑依賴規則的標準檢查：`--start-cohort`、`--fill-noise`、`--oos-split-2023`

- `--start-cohort monthly|quarterly`：對每個上線日為 start_idx 各跑變體與基準（引擎 `simulate_regime(start_idx=…)` 已支援），回報 Δ 分布（均值 / 最差 / 翻掛數）與觸發日集合；guard 類的 C1 改為 cohort 分位數。`--fill-noise σ --seeds n`：成交價乘 (1+N(0,σ))，回報觸發集合 / regime 一致率與十格閘門數分布（判準：與基準相同 ≥ 16/20、閘門數不變）。`--oos-split-2023`：對 OOS 另印「只取 2023」與 OOS2 分開的 Δ/t，明示四 OOS 格只有兩個獨立觀察。
- 動機：這三項本輪由驗證者手寫（scratchpad 腳本各 200–1,100 次引擎模擬），每項都翻轉了實作者的結論；標準化後任何 guard 或倉位覆蓋層在實作階段就會看到。

### P4. 現貨紙上前向模組 `live/paper.py`

- 內容：每日 00:00 UTC 收盤後 (1) 從 Binance **現貨** K 線重算 ≥ 250 根的 EMA50 狀態（起點收斂最壞 ~210 根，不沿用回測的狀態序列）；(2) 產生目標曝險並以次日開盤市價「紙上成交」，成交價用實際開盤價 ± 登記滑點，費率用現貨模型（0.10%，BNB 抵扣另列 0.075%）；(3) 份額法 NAV、同起點持有 NAV、比值、比值高水位回撤、90/180/365 根滾動比值（P2 記錄型）、EMA50 狀態、每筆成交與原因；(4) 週報：對照回測同期（regime_key 逐日比對現貨 vs 永續 K 線）。事前登記：上線日、費率與滑點模型、評估視窗（≥ 12 個月或每標的 ≥ 20 回合）、停止規則（策略連續 6 個月 rel_dd 深於回測 IS/OOS 分布 p95、或 regime 與回測資料源不一致 > 5% 根）。
- 動機：使用者的指示是「優化到一定程度後開始現貨紙上前向」；本輪證明優化已到邊際（連續 4 輪無冠軍、方向全關），且執行面的三個問題（資料源、時點、成本路徑依賴）只有前向能回答。

5. **guard_cohort_calibration_record_only**（依賴 P2 `record` + P3 `--start-cohort`）：純量測、不設計動作。對 `ema50_plain`（單標的與組合）以每月上線日為 cohort，算累計比值落後、比值高水位回撤、90/180/365 滾動落後的分布（p50/p90/p95/p99、首次穿 −20%/−30%/−40% 的時間分布），並把「觸發後 12 個月策略 vs 持有」分佈列出。目的：回答「X 要多大才是尾部事件而非設計行為」與「觸發後是否還有可挽回的價值」；判準是描述性的（報告必列 cohort 分布表），任何動作型規則都要等前向 ≥ 6 個月的實際記錄再開新變體。

## 16. 對評估器 / 迴圈流程的建議（不改 regime.py）

1. **安慰劑零假設設計事前登記**：clip 在「回合內打亂時點」與「跨回合置換」之間六格百分位 41 vs 83，該選保留最多變體結構的那一種；「滿足全部數值門檻的比例」要排除被成交上限機械擋掉的情形（D1/D2/D4 的 0% 無鑑別意義）。
2. **OOS 獨立觀察數**：OOS ⊃ OOS2，報表加印「OOS 只取 2023」與 OOS2 分開的 Δ/t；凡假設是從某標的 OOS 觀察讀出來的（本輪 clip 由第 3 輪 A1 vs A0 在 BTC OOS 上觀察而來），該標的 OOS 格標記為「已用於選擇」。
3. **guard 類的必做檢查**：起算日 cohort（每月 / 每季）、資料起點後移 0–120 根、成交價雜訊 σ=0.05% × 20 種子（觸發集合相同 ≥ 16/20）、起算點收斂（從 2022/2023/2024/2025-01-01 各起算，盲區後一年曝險一致率 ≥ 95%）、holdout 首次觸發距基期 < 180 根一律標記為起點人工產物；「OOS 無觸發 → Δ=0」不得計入通過，另報每格 min lag 距 X 的距離。
4. **壓力情境的資金費率對比值型閘門**：持有基準不付資金費率而策略付 → 比值結構性下滑製造假觸發（BTC 2025-09-29）；對現貨執行此情境無意義，guard 類 C5 應排除或讓基準也扣費率。
5. **延遲一根規則**：凡優勢來自 1 根時點的變體，延遲一根情境下「由基準過翻掛」直接判 executable fail；成交數上限保留 ≥ 10% 餘裕（clip ETH 只剩 2 筆、BNB 1.58×）。
6. **基準結果檔補齊**：`results/variants/ema50_plain.json` 無 stress 區塊、`results/holdout/ema50_plain.json` 無 n_fills / rel_dd / stress，第 3 輪 §13.6 已提，本輪三位實作者各自重跑到 scratchpad；用 `evaluate_variant.py --variant ema50_plain --symbols … --alt-split --stress --out results/verify/baseline_holdout` 存一份正式基準列。
7. **變體檔自檢的 import 順序**：`from abgt import` 先於 `sys.path.insert`，直接 `python experiments/variants/<id>.py` 會 ModuleNotFoundError；在 CLAUDE.md 註明 `PYTHONPATH=. python …` 或把 insert 移到頂層 import 前；自檢 (4) 的切點數改為每 20 根一個（≥ 100）。
8. **機制檢查的跨標的同向要求**：對任何倉位覆蓋層，事前判準加「BTC/ETH/SOL/BNB 機制檢查至少 3/4 同向」；本輪 clip 四標的 2 正 2 反，Sharpe 口徑門檻被標的抽樣主導。

## 17. 現貨紙上前向：本輪決定的起始規格

| 項目 | 規格 |
|------|------|
| 策略 | `ema50_plain` 原樣（close > EMA50 滿倉否則空手；EMA50 SMA 起算；收盤判定、次日開盤成交）；**不掛** A3 / clip 倉位覆蓋層 |
| 標的 / 市場 | Binance 現貨 BTC/USDT、ETH/USDT；先各自單標的帳，組合層待 P1 |
| 運行閘門 | 引擎 `lag_stop = 0`；記錄型指標每日另算（比值、比值高水位回撤、90/180/365 滾動、盲區標示）；**無自動動作**，異常只通知 |
| 成本模型（登記） | 費 0.10%/邊（BNB 抵扣版 0.075% 另列）、滑點 0.05%；與回測 0.05%+0.02% 的差異在週報逐日對照 |
| 狀態重算 | 每日以 ≥ 250 根現貨 K 線重算 EMA50 與 regime，不沿用回測狀態；上線前先跑 §15.4 現貨資料源檢查與 §15.3 收盤時點檢查 |
| 評估視窗 / 判準 | ≥ 12 個月或每標的 ≥ 20 回合；判準是「前向分布與回測 2023→ 分布一致」（翻轉次數、回合長度、相對落後深度落在 p10–p90），不是「贏過持有」 |
| 停止規則（登記） | regime 與回測資料源不一致 > 5% 根、連續 6 個月 rel_dd 深於回測 OOS cohort p95、或成本實際值超過登記值 2 倍 |
| 之後 | 12 個月後決定是否接 `live/` Binance 測試網下單；期間迴圈不再開 EMA50 濾波 / 倉位覆蓋 / 相對落後閘門變體 |
